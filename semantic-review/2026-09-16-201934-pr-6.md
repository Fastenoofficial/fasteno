# Maintenance gate with signed Razorpay continuity

The change moves maintenance enforcement into Node.js middleware so one exact environment value stops ordinary traffic while retaining a narrow Razorpay callback path and operator unlock. It closes the prior review’s protected-webhook gap: middleware checks route/method/query/signature shape, while the route verifies bounded raw bytes before demo or database behavior. The gate, downstream authorization, and cache/CSP composition work, but the operator token is not time-limited at the server and origin enforcement fails open when the header is absent. The public-host source also needs correction or deployment proof before it can support canonical redirects and cryptographic host binding.

**Watch for:** **confirmed (high)** the deterministic bypass cookie remains valid for as long as the same secret is deployed, not 15 minutes; **confirmed (high, operational)** signed callbacks continue into missing-006 and migration-010 lock states; **confirmed (medium)** originless unlock POSTs are accepted; **likely (medium)** Next’s Node middleware URL normalization can collapse `www`/apex host behavior; **confirmed (medium)** no committed tests protect this security matrix.

**Verdict**: NEEDS_CHANGES

## High-level view

`MAINTENANCE_MODE` activates only for exact `1`, invalid bypass-secret configuration fails closed, and Next 15.5 expands `/:path*` across root, static assets, APIs, data/RSC transports, and page POSTs. Offline smokes confirmed anonymous root, public-static, API, and synthetic Server Action requests all stop at the maintenance response.

The unlock bounds form data to 1 KiB, uses timing-safe comparison for valid 64-hex candidates, and emits a Secure, HttpOnly, SameSite=Strict, path-root `__Host-` cookie containing only a host-derived HMAC. Its `Max-Age=900` is browser-only because the HMAC carries no issuance or expiry time, and the Origin comparison runs only when the header is present.

The Razorpay exception admits only exact no-query POSTs with a configured webhook secret and 64-hex signature shape. The route preserves at most 256 KiB of exact bytes for timing-safe HMAC verification, rejects unsigned demo requests, and emits no-store responses; a valid callback still reaches payment RPCs during migration maintenance.

Bypassed requests resume Supabase session refresh and `/account`/`/admin` guards, while Server Actions retain their own authorization. Maintenance HTML is no-store/noindex under its restrictive CSP, bypassed cacheable API/static responses remain no-store, and disabled mode preserves ordinary API caching. Canonical query cloning and 308 status are correct in source, but the redirect and cookie HMAC both depend on `request.nextUrl.hostname`, which was not the incoming Host in the standard Next Node server path tested locally.

No repository tests cover these branches. TypeScript, diff-integrity, runtime/matcher analysis, and provider-isolated request smokes passed; platform host mapping, real session refresh, production image inventory, and migration/provider retry timing remain unverified.

<details>
<summary>Details</summary>

## Operator token is browser-expiring, not server-expiring

The cookie is `HMAC(secret, "fasteno-maintenance-bypass-v1\0" + hostname)`, and validation checks only that deterministic value (`middleware.ts:19-50`). `Max-Age=900` is attached at issuance (`middleware.ts:190-200`), but no signed timestamp or server time check exists. **Confirmed:** repeated unlocks produced the same 43-character token, so a copied cookie remains replayable while `MAINTENANCE_MODE=1` and the same secret is deployed, including a later window that reuses it.

The bypass leaves account/admin authorization intact but reopens public application/API writers. Encode an issuance timestamp in the signed payload, reject age over 900 seconds server-side, and rotate the secret for every maintenance window.

## Unlock origin policy accepts originless POSTs

Origin is rejected only inside `if (origin)` (`middleware.ts:160-170`). **Confirmed:** a valid originless form POST returned 303 and a cookie, while a cross-origin value returned 403. The body and secret controls do not establish same-origin provenance.

Require exact Origin, or an equivalent trusted signal such as validated platform host plus `Sec-Fetch-Site: same-origin`. A command-line unlock, if needed, should use an explicit separately authenticated path.

## Public host depends on Next’s normalized middleware URL

Cookie signing and the disabled-mode canonical redirect use `request.nextUrl.hostname` (`middleware.ts:45`, `middleware.ts:191`, `middleware.ts:207-231`). **Likely:** this is not a reliable public-host source for Node middleware. Next 15.5’s standard Node server constructs the middleware URL from configured `fetchHostname`; local requests carrying `Host` and `X-Forwarded-Host` as `www.fasteno.in` still exposed `localhost`, did not redirect, and accepted the same cookie when manually replayed through `127.0.0.1`.

Vercel may use a different adapter, which could not be checked without provider contact. Use a strictly normalized/allowlisted platform-trusted host source, or retain the host-aware `next.config` redirect and bind the cookie to that same source. Add an immutable-deployment smoke for apex and every alias.

## Signed callbacks stay active while payment schema changes

The maintenance exception exits before every other gate branch (`middleware.ts:143-152`, `middleware.ts:210`), then HMAC-valid events call payment persistence (`app/api/razorpay/webhook/route.ts:29-123`). **Confirmed operational risk:** before 006, the payment RPCs created by that migration are unavailable (`supabase/migrations/006_security_hardening.sql:95-263`), so authentic deliveries return retryable 500s and require reconciliation. Migration 010 holds `SHARE ROW EXCLUSIVE` on `orders` from line 23 to commit, so callbacks can wait until function timeout and retry after release.

Successful callbacks can also increment coupon state, trigger auto-ship, and send email; the operator cookie likewise unlocks the whole application for an authenticated operator. Drain checkout and operator writes, disable auto-ship and cron/other writers, monitor non-2xx deliveries, record the interval, and reconcile provider events before reopening. Explicitly choose whether 010 drains callbacks or accepts a measured retry queue—the gate does not pause them.

## Maintenance and webhook branches have no durable regression suite

No test or spec files cover the new middleware or route branches. **Confirmed:** current evidence is limited to `npx tsc --noEmit --incremental false`, `git diff --check`, Next static-info analysis, and local Node middleware/route smokes.

Add table-driven coverage for environment values, invalid secrets, method/path/query variants, body limits, cookie age/host checks, auth continuation, headers, canonical query preservation, and demo/live webhooks. **Not tested:** Vercel public-host mapping, real Supabase session refresh/admin denial after bypass, production persisted image origins, full `next build` (skipped because `next/font/google` would contact an external provider), and callbacks against actual 006/010 lock states.
