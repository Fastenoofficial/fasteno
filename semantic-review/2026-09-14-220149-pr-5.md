# Atomic product administration and read-only media inventory

Task #5 replaces user-facing product deletion with reversible archiving, moves duplication and bulk state/category transitions into database RPCs, adds immutable administrator activity, standardizes low-stock views, and introduces a read-only media/reference inventory with CSV export. The RPC boundary correctly provides bounded complete-set validation, draft-safe duplication, featured-order compaction, and same-transaction activity. Three behavioral blockers remain: cross-path deadlock potential, product-editor mutations missing from the advertised activity history, and blank persisted media values disappearing from the report. **Watch for:** **confirmed** category/product lock inversion; **confirmed** product-editor audit bypass; **confirmed** blank-reference omission; **likely** residual `anon`/`service_role` RPC ACLs under Supabase defaults; **confirmed** unbounded in-memory report assembly; **confirmed** missing task-specific tests.

**Verdict**: NEEDS_CHANGES

## High-level view

Archive, bulk state/category changes, and featured membership converge on `admin_manage_products`; duplicate creation uses a separately locked suffix allocator. Complete/unique/500-row validation, active-only featuring, draft reset, compaction, and transactional activity are verified, but category changes lock category-before-product while duplicate/editor paths can lock product-before-category.

Activity rows have database-derived actors/timestamps, allowlisted metadata, update/delete prevention, and admin-only authenticated reads. The normal product editor still writes `active` and `category_id` directly, so the visible history is not complete, and migration 009 should explicitly clear Supabase’s named default function grants rather than relying on `PUBLIC` revokes alone.

Low stock is consistently defined as active products with stock at or below the shared threshold of five. The dashboard exact-count query is separate from its six-row preview, and the product filter/table use the same predicate.

The media report recursively and paginatedly walks `product-images`, pages all required database sources, recognizes only exact bucket public URLs, emits all six statuses, exports quoted admin-only CSV, and exposes no deletion. Blank values are filtered before classification, and the full historical dataset is duplicated through several in-memory structures per request.

<summary>Issues (6)</summary>

1. **P1 · Category/product lock inversion — confirmed** — Category changes lock a category before products, while duplicate and editor paths can hold a product before requesting a category foreign-key lock; impose one lock order across every writer and add a two-session test.
2. **P1 · Product-editor audit bypass — confirmed** — Saving `active` or `category_id` directly creates no matching activity despite the UI’s blanket transactional-history claim; route these transitions through the audited RPC or narrow the claim and enforce the intended write surface.
3. **P1 · Blank-reference blind spot — confirmed** — Blank persisted image values are dropped before the invalid classifier, understating both invalid values and total references; preserve present blank/whitespace values and report them as invalid.
4. **P2 · Residual RPC ACLs — likely** — `PUBLIC`-only revokes may leave Supabase’s direct `anon`/`service_role` EXECUTE grants in place; revoke every unintended named role, re-grant `authenticated`, and assert the deployed ACL.
5. **P2 · Unbounded report materialization — confirmed** — Historical database rows and CSV output are assembled into multiple unbounded arrays/strings; stream or incrementally aggregate while retaining an explicit completeness signal.
6. **P2 · Missing invariant tests — confirmed** — No tests exercise the SQL transactions, ACL/RLS rules, concurrency, classification, traversal, or CSV safety; add database integration and focused inventory/export tests.

## Atomic product RPCs and cross-writer lock inversion

**Verified:** edit and bulk controls expose “Archive,” both archive paths call `admin_manage_products`, and the only physical `products.delete()` is internal compensation for a just-created row whose requested feature transition failed (`components/admin/ProductForm.tsx:372-381`, `components/admin/BulkActionsBar.tsx:140-152`, `components/admin/actions.ts:218-237`, `components/admin/actions.ts:276-301`). No task #5 product action exposes physical deletion.

**Verified:** duplicate allocation holds an advisory transaction lock and retries unique violations. A successful insert clears `images`, sets stock/order to zero, sets `featured` and `active` false, blanks both SEO fields, and commits its activity in the same transaction (`supabase/migrations/009_admin_operations_safety.sql:428-529`).

**Verified:** application and database layers require a non-empty unique set of at most 500; the RPC rejects missing products and inactive feature targets, performs membership compaction, inserts activity, and then returns the complete selection (`components/admin/bulk-actions.ts:25-66`, `supabase/migrations/009_admin_operations_safety.sql:194-216`, `supabase/migrations/009_admin_operations_safety.sql:244-395`). Archive, activate, deactivate, feature, unfeature, and category-change RPC executions are atomic with required ordering compaction and activity.

**Confirmed concern:** `admin_manage_products` takes category advisory/row locks before product rows (`supabase/migrations/009_admin_operations_safety.sql:221-248`), while `admin_duplicate_product` locks the source product before its insert requests a foreign-key key-share lock on that product’s category (`supabase/migrations/009_admin_operations_safety.sql:428-494`). A concurrent assignment of that product to its current category can hold the category and wait for the product while duplication holds the product and waits for the category. Direct category edits use the same product-first order (`components/admin/actions.ts:125-167`). Put duplicate and ordinary edits behind the same advisory/row-lock protocol as bulk category operations.

## Database-stamped history versus editor bypass

**Verified:** metadata is action-allowlisted, the insert trigger overwrites actor/time from `auth.uid()` and transaction time, update/delete triggers reject changes, and authenticated SELECT is gated by admin RLS (`supabase/migrations/009_admin_operations_safety.sql:36-158`). RPC-created history is database-attributed, append-only, and application-admin read-only.

**Confirmed concern:** the ordinary product form includes `category_id` and `active` in a direct table update (`components/admin/actions.ts:125-167`). Activating, deactivating, or recategorizing there creates no corresponding activity, while the new activity page says successful product operations are transactionally recorded (`app/admin/activity/page.tsx:85-87`). Route those transitions through the audited transaction; if only bulk/archive paths are intentionally audited, state that narrower scope and prevent the history from being treated as complete.

## Definer checks versus Supabase function ACLs

**Verified:** both SECURITY DEFINER operations use an empty search path, schema-qualified objects, `auth.uid()`, and an explicit `is_admin()` check before mutation (`supabase/migrations/009_admin_operations_safety.sql:163-188`, `supabase/migrations/009_admin_operations_safety.sql:407-423`). Unauthorized callers fail closed in the function bodies.

**Likely concern:** migration 009 revokes EXECUTE only from `PUBLIC` before granting `authenticated` (`supabase/migrations/009_admin_operations_safety.sql:398-402`, `supabase/migrations/009_admin_operations_safety.sql:534-537`, `supabase/migrations/009_admin_operations_safety.sql:563-567`). Standard Supabase defaults also grant public-schema functions directly to named roles, which a `PUBLIC` revoke does not remove; the repository’s earlier hardening explicitly revokes `anon` and `authenticated` for this reason (`supabase/migrations/004_security_hardening.sql:35-40`). Body checks mitigate escalation, but the migration should revoke `anon`/`service_role` explicitly and verify the final ACL with `has_function_privilege`.

## Blank values bypass otherwise complete media classification

**Verified:** Storage traversal is recursive and offset-paginated; products include active and archived rows, and categories, banners, and historical `order_items` are loaded without state filters (`lib/admin-media-inventory.ts:180-232`, `lib/admin-media-inventory.ts:237-321`). The classifier requires exact probe origin/prefix with no credentials, query, or fragment before decoding a safe object path (`lib/admin-media-inventory.ts:135-168`). Nonblank values can produce referenced, unreferenced, missing, external, local, and invalid rows.

**Confirmed concern:** `collectReferences` appends only non-empty `value.trim()` values (`lib/admin-media-inventory.ts:243-246`), making the classifier’s empty-input `invalid` branch unreachable (`lib/admin-media-inventory.ts:135-136`). Empty product array entries, required banner image values, and historical empty `order_items.image` values vanish from `invalidValues` and `totalReferences`. Skip null optional fields, but preserve present blank values with their sources as invalid.

**Verified:** the media page states there is no cleanup action, task #5 contains no Storage removal call, and the endpoint is admin-gated, no-store, formula-prefix escaped, and quote/newline escaped (`app/admin/media/page.tsx:115-126`, `app/api/admin/export/media/route.ts:9-18`, `app/api/admin/export/media/route.ts:28-35`, `app/api/admin/export/media/route.ts:78-83`). The feature exposes no media deletion and safely quotes every collected CSV cell.

## Full historical inventory is multiplied in memory

**Confirmed concern:** each database source is accumulated into an unbounded array, references are copied into maps/report rows, and export creates another row matrix plus a final CSV string (`lib/admin-media-inventory.ts:99-113`, `lib/admin-media-inventory.ts:289-344`, `app/api/admin/export/media/route.ts:15-18`, `app/api/admin/export/media/route.ts:63-75`). Storage stops above 100,000 objects, but historical `order_items` has no bound; mature data can exhaust serverless memory/time, and page load plus export repeats the scan. Stream/chunk export and incrementally aggregate the UI, or surface a documented incomplete result instead of calling a bounded report complete.

## Shared active-stock threshold and independent preview count

**Verified:** `LOW_STOCK_THRESHOLD` is defined once as five; dashboard count and preview both apply `active = true` and `stock <= threshold`, while only the preview is limited to six. The product filter and row highlighting use the same semantics (`lib/admin-constants.ts:1-5`, `app/admin/page.tsx:101-111`, `app/admin/products/page.tsx:73-86`, `components/admin/ProductsTable.tsx:138-142`).

## Task #5 lacks executable database and inventory checks

**Confirmed concern:** no tests reference the new RPCs, activity table, low-stock contract, inventory classifier/traversal, or CSV endpoint, and `package.json` has no test command (`package.json:5-10`). `npm run build` passes, but it cannot execute PostgreSQL, inspect deployed ACL/RLS state, force lock interleavings, or exercise paginated Storage fixtures. Add integration tests for rollback, draft defaults, actor spoof rejection, append-only ACLs and concurrency, plus inventory/export tests for pagination, exact URL parsing, every status, blank values, and formula-leading cells.
