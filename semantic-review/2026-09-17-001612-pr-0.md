# Modern Supabase server-secret compatibility

The change makes `SUPABASE_SECRET_KEY` the preferred credential for privileged Supabase access while retaining `SUPABASE_SERVICE_ROLE_KEY` as a fallback. The service factory and limiter HMAC resolver share that precedence, and checkout, newsletter, payment, upload, and service-owned admin paths still converge on the factory. Server-only boundaries and compiled-bundle canaries confirm that neither credential value reaches browser chunks; `.env.example` also tells operators to configure only one. The capability flag does not apply the factory’s whitespace normalization.

Watch for: **confirmed** — `isServiceRoleConfigured` can report a usable credential when `createServiceClient()` returns `null`; normalize the capability check or derive both behaviors from one resolver.

**Verdict**: NEEDS_CHANGES

## High-level view

`createServiceClient()` trims and prefers the modern secret before falling back to the trimmed legacy JWT. **confirmed** — `isServiceRoleConfigured` tests raw strings, so `SUPABASE_SECRET_KEY="   "` reports capability while privileged operations fail closed.

Checkout order/stock/guest operations, Razorpay persistence and refunds, newsletter insertion, admin upload, and admin RLS-bypass operations obtain elevated access through `createServiceClient()` or `requireServiceClient()`. Session clients remain limited to authenticated/RLS-controlled admin work.

The factory and limiter are marked `server-only`. Shared `lib/config.ts` causes environment-variable names to appear in browser code, but compilation canaries confirm that non-`NEXT_PUBLIC_` credential values are not inlined. Limiter targets remain HMAC-SHA-256-derived, truncated to 128 bits, and keyed by `RATE_LIMIT_HASH_SECRET`, modern Supabase secret, legacy secret, or Upstash token in that order.

`.env.example` calls the modern key preferred, labels the legacy key a fallback, and explicitly says “Configure only one server secret.” **confirmed** — no focused tests cover the modern/legacy environment matrix, leaving precedence and normalization behavior without regression protection.

## Whitespace-only modern keys create a false capability signal

**confirmed** — `lib/config.ts` evaluates `Boolean(process.env.SUPABASE_SECRET_KEY || process.env.SUPABASE_SERVICE_ROLE_KEY)`, while the factory trims both candidates. With only a whitespace modern value, the flag is `true` and the factory returns `null`. The flag currently has no consumers, so the mismatch is latent, but its exported contract does not represent the capability it names.

Use `Boolean(process.env.SUPABASE_SECRET_KEY?.trim() || process.env.SUPABASE_SERVICE_ROLE_KEY?.trim())`, or centralize normalized detection in a server-only resolver.

## Privileged operations retain one credential-selection point

```text
checkout/order/guest helpers ──────────────────┐
Razorpay verify/webhook/refund ────────────────┤
newsletter route ──────────────────────────────┼─> createServiceClient()
admin service bypasses ────────────────────────┤      modern -> legacy
admin upload ──> requireServiceClient() ───────┘
```

Direct credential reads exist only in the factory, capability flag, and limiter resolver. Route responses, serialized props, and payment payloads never handle either raw value, and upload cannot fall back to an anonymous or session client.

## HMAC fallback follows the credential migration

The limiter trims both Supabase candidates in modern-first order and uses the selected value only as an HMAC key. Moving from legacy to modern resets in-flight limiter buckets once but exposes neither credentials nor raw targets; configuring the documented independent `RATE_LIMIT_HASH_SECRET` avoids that rotation coupling.

## Validation coverage

TypeScript and `git diff --check` pass. Production compilation emitted browser chunks containing neither secret canary; the later static-data phase could not complete because the repository’s existing live catalog environment failed its Supabase fetch, so no full build pass is claimed.

**confirmed** — no focused automated tests cover modern-key precedence, legacy fallback, whitespace normalization, or HMAC fallback selection. Add a small environment-matrix test around the shared resolver/factory behavior so compatibility does not drift again.
