# Responsive product and cart interaction polish

Task #3 reshapes the product and cart experiences into responsive card and action layouts, moves sharing into the product purchase controls, and adds more explicit assistive semantics. Product prices and copy still come from the same fields; stock and quantity gates, cart persistence and mutations, totals, shipping, checkout, related products, and recently viewed retain their existing paths. Two client-facing regressions remain in the newly arranged controls. Watch for: **confirmed** — the fallback share popover is clipped on common phone widths; **confirmed** — the added-to-cart live message can announce a quantity that was not added and can miss repeated additions.

**Verdict**: NEEDS_CHANGES

## High-level view

The product page continues to render the same catalog object through `PriceTag`, stock badges, details, recommendations, and recently viewed. The cart still delegates mutations and localStorage persistence to `useCart`, applies the same 10-unit cap, ₹1,499 free-shipping threshold and ₹99 fee, and links to `/checkout`.

The responsive structure stacks product attributes on narrow screens, makes gallery thumbnails horizontally scrollable, places cart controls on their own mobile row, and aligns Add to Cart, Wishlist, and Share in a compact action grid. **confirmed** — placing Share in the second column while left-aligning its fixed-width fallback popover pushes part of the popover beyond common mobile viewports, where the global horizontal-overflow rule clips it.

The accessibility pass adds contextual quantity labels, live quantity output, free-shipping value text, decorative-icon hiding, and a polite cart-loading status. Native sharing, WhatsApp/copy fallback, outside-click dismissal, and Escape dismissal remain behaviorally unchanged. **confirmed** — the new add confirmation reads the selector’s current quantity rather than a snapshot of the submitted mutation, and a second identical addition does not produce a fresh live-region update.

1. **Mobile share fallback clipping** — **confirmed** — the fixed-width fallback panel is left-aligned to the second mobile action cell and is clipped on common phone widths. Right-align or viewport-constrain it below `sm`.
2. **Mutation-incorrect cart announcement** — **confirmed** — the live region reads mutable selector state and does not retrigger for identical repeat additions. Snapshot the submitted quantity and emit a fresh announcement for every mutation.

<summary>Details</summary>

### Fallback share popover escapes the mobile action grid

`AddToCartPanel` now renders Wishlist and Share as the two cells of a mobile `grid-cols-2` row (`components/catalog/AddToCartPanel.tsx:43-83`), while `ShareButton` anchors its `w-48` popover to the left edge of the second cell until `sm` (`components/product/ShareButton.tsx:83-85`). **confirmed** — with 16px page padding and the 12px grid gap, the 192px panel extends beyond the viewport below roughly 396px; `body { overflow-x: hidden; }` clips the WhatsApp/copy controls (`app/globals.css:45-46`). Align the panel to the right edge on mobile, or otherwise constrain it to the viewport.

### Added-to-cart status is not bound to the submitted mutation

The click handler submits `quantity` and sets a boolean `added` flag (`components/catalog/AddToCartPanel.tsx:48-50`), while the live region interpolates the still-editable `quantity` for two seconds (`components/catalog/AddToCartPanel.tsx:85-87`). **confirmed** — changing the selector during that window announces the new value even though the previous value was added; clicking Add to Cart again with the same value also produces no live-region change for the second cart mutation. Capture the submitted quantity and drive each announcement from a per-mutation value or event key.

### Validation

`git diff --check`, `npx tsc --noEmit --pretty false`, and `npm run build` passed; the production build generated all 76 pages.
