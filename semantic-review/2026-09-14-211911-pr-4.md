# Resilient storefront rendering with privacy-scoped commerce analytics

This change adds route-level loading/error states, sanitized image fallbacks, a CMS-backed hero carousel, hardened cart/wishlist hydration, and typed GA4 commerce events. Catalog outages now reach the error boundary, and checkout stays inert until persisted cart state loads. The task #3 share-clipping and mutable-announcement findings are addressed. The explicit event API is allowlisted, but its privacy guarantee is bypassable by global GA initialization and a fail-open pathname fallback; analytics and ARIA state also diverge from reported behavior in several places. Watch for: **likely** — automatic GA4 events can observe raw document metadata and guest bearer navigation outside the safe emitter; **confirmed** — unknown paths are transmitted verbatim; **confirmed** — the new cart line cap is enforced only after reload.

**Verdict**: NEEDS_CHANGES

## High-level view

Catalog images now pass through server-side normalization before stable `StorefrontImage`/`StorefrontPicture` fallbacks. Live catalog failures throw into `app/error.tsx`, loading states expose statuses, and checkout waits for cart hydration. **confirmed** — stored carts truncate to 100 lines, but live additions remain unbounded, so a large valid cart loses later lines after reload.

The analytics API uses fixed event/list contexts, converts paise, buckets query length, excludes checkout form/coupon/error/Razorpay data, overrides explicit event location/referrer/title, suppresses named sensitive routes, and session-deduplicates purchases. **likely** — these controls cover only `emit`; GA4 is initialized on every route, so property-configured automatic events can use raw document metadata, including the temporary guest bearer URL.

Manual route views redact product, category, and guide identifiers. **confirmed** — every other pathname passes through unchanged, while deduplication compares the redacted value; unknown paths fail open and navigation between two products or categories loses the second page view.

Checkout subtotal, shipping, discount, GST, COD threshold, productId/quantity request shape, server repricing, stock reservation, and the ten-unit line cap retain their established calculations. Guest credentials stay outside `Order` and exchange into a path-scoped HttpOnly cookie before the clean order page. **confirmed** — add-to-cart analytics records the requested amount rather than the amount accepted by the ten-unit cap.

The carousel pauses for hover, focus, hidden documents, and reduced motion; inactive slides are inert and controls are labeled. **confirmed** — the search popup can report itself collapsed while visible and combines tabbable buttons/status nodes with an active-descendant listbox; `ProductCard` also hides a still-interactive anchor from the accessibility tree.

### Global GA initialization bypasses the explicit event allowlist

```text
storefront interaction
  -> typed trackStorefrontEvent
  -> field-specific cleaners / fixed context
  -> emit
  -> redacted location + empty referrer + pathname title

root layout
  -> gtag('config', ...)
  -> GA4 automatic / enhanced-measurement event
  -> browser document URL, referrer and title
```

Explicit calls send query-length buckets, fixed filter names/counts, monetary/count data, and sanitized transaction/catalog fields; no call passes query text, contact/address/PIN fields, coupon/error text, guest credentials, order numbers, or Razorpay identifiers (`lib/analytics-client.tsx:188-346`, `components/checkout/CheckoutForm.tsx:221-333`). Purchase events are suppressed for the same transaction in current-tab session storage (`lib/analytics-client.tsx:300-320`).

**likely** — `send_page_view: false` prevents the config-triggered page view, but does not establish that GA Enhanced Measurement history, scroll, outbound-click, or site-search events are disabled (`lib/analytics.tsx:16-34`; global mount at `app/layout.tsx:47-48`). Guest checkout pushes `/order/<id>/access?token=<bearer>` before exchange (`components/checkout/CheckoutForm.tsx:233-237`), which a GA history listener can observe without calling `analyticsPath`. Disable automatic collection and enforce that deployment setting, or gate/consent-deny the tag on sensitive transitions; exchanging the bearer before routing to a clean URL removes the highest-impact value from browser history.

### Route redaction fails open and collapses catalog navigation

**confirmed** — after suppressing named sensitive prefixes and parameterizing three dynamic routes, `analyticsPath` returns every unmatched pathname unchanged (`lib/analytics-client.tsx:348-356`). The root tracker sends that value as location, path, and title, including arbitrary 404/future paths (`lib/analytics-client.tsx:364-371`). Allowlist known public routes and map everything else to a fixed unknown-route value.

**confirmed** — `lastPath` stores the redacted path as its duplicate key (`lib/analytics-client.tsx:360-370`). `/product/a` and `/product/b` both become `/product/:product`, while two categories both become `/shop/:category`; the second client navigation emits no page view. Compare the raw pathname only in memory while continuing to transmit the redacted value.

**likely** — route/list/item trackers record their ref signatures before knowing whether `emit` succeeded, while both GA scripts use `afterInteractive` (`lib/analytics-client.tsx:364-424`, `lib/analytics.tsx:16-33`). An effect that runs before `window.gtag` exists is marked seen and never retried. Bootstrap the queue before mounting trackers or retry failed initial emissions after initialization.

### Cart limits and analytics disagree at mutation boundaries

**confirmed** — `MAX_CART_ITEMS` applies only while parsing stored JSON (`lib/cart-context.tsx:20,82`); a new product still appends with no line-count check (`lib/cart-context.tsx:188-215`). More than 100 valid distinct products remain visible and persisted for the current session, then only the first 100 survive hydration. Enforce the limit in `addItem` and expose a refusal instead of silently discarding cart state on reload.

**confirmed** — `addItem` accepts only room remaining under ten units, but card and PDP handlers always emit the requested quantity (`lib/cart-context.tsx:188-198`, `components/ui/ProductCard.tsx:114-121`, `components/catalog/AddToCartPanel.tsx:53-60`). At quantity nine, requesting three adds one but reports three; at ten, a no-op still emits `add_to_cart`. Emit the accepted positive delta and use it for the live announcement as well.

### Search and product cards use contradictory accessibility state

**confirmed** — with recent searches and an empty focused input, the popup is visible while `aria-expanded="false"` and `aria-controls` is absent (`components/search/SearchAutocomplete.tsx:213-242,250-369`). Typed suggestions keep focus on the input via `aria-activedescendant`, but each option is also a tabbable `<button role="option">`, and status nodes sit directly inside the listbox (`components/search/SearchAutocomplete.tsx:253-329`). Associate every visible popup, keep active-descendant options out of the tab order, and move live statuses outside the option-only listbox.

**confirmed** — autocomplete failure is recorded as `resultCount: 0`, conflating service failure with a successful zero-result search (`components/search/SearchAutocomplete.tsx:151-159,265-273`). Omit the count on failure or add a fixed outcome dimension.

**confirmed** — the product image anchor uses `tabIndex={-1}` and `aria-hidden="true"` while remaining pointer- and programmatically interactive (`components/ui/ProductCard.tsx:45-52`). Make the image non-interactive and extend the visible name link, or expose it with valid link semantics and focus behavior.

### Regression coverage stops at compilation

**confirmed** — there is no test script or matching unit/component coverage for analytics redaction, purchase deduplication, storage caps, checkout hydration, image fallback, or combobox state (`package.json:5-9`). Type checking, scoped `git diff --check`, and the production build pass, with all 76 routes generated. Add focused tests for the privacy allowlist, sensitive navigation, dynamic route views, accepted cart deltas, storage limits, and combobox states.
